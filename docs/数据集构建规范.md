# 数据集构建规范

为了保证我们训练出的 YOLO 模型能够稳定运行，且团队成员在处理数据时有一致的标准，请大家在构建和合并数据集时严格遵循以下规范：

## 1. 目录结构规范
我们将 `archive1` 和 `archive2` 等原始数据集清洗后，统一输出到 `dataset/` 目录下。合并后的 `dataset` 文件夹应严格遵循 YOLO 格式的目录树：
```text
dataset/
├── data.yaml           # 数据集配置文件（包含类别和路径信息）
├── train/              # 训练集 (建议占 70%-80%)
│   ├── images/         # 训练集图片 (.jpg, .png 等)
│   └── labels/         # 训练集标签 (.txt)
├── valid/              # 验证集 (建议占 10%-20%)
│   ├── images/
│   └── labels/
└── test/               # 测试集 (建议占 10%，可选)
    ├── images/
    └── labels/
```

## 2. 标签 (Labels) 格式设定
YOLO 采用纯文本 (`.txt`) 的标注格式，**每个图片对应一个同名的 .txt 文件**。
标签文件内的每一行代表一个被检测的目标，格式如下：
```text
<class_id> <x_center> <y_center> <width> <height>
```
- **class_id**: 类别索引（从 0 开始计数，例如 0 代表 plastic_bottle）。
- **x_center, y_center**: 目标边界框的中心点坐标，**必须归一化** 到 `[0, 1]` 之间（坐标值除以图像的宽/高）。
- **width, height**: 目标边界框的宽度和高度，**必须归一化** 到 `[0, 1]` 之间。

## 3. data.yaml 配置要求
位于 `dataset/data.yaml` 的文件必须准确反映当前数据的状态。内容应如下（路径建议使用相对于训练运行目录的相对路径或绝对路径）：
```yaml
# 示例配置
train: ./dataset/train/images
val: ./dataset/valid/images
test: ./dataset/test/images

# 类别数量
nc: 1

# 类别名称
names: ['plastic_bottle']
```

## 4. 图像预处理与清洗 (OpenCV使用建议)
在将原始数据移动到 `dataset/` 之前，可以使用 `src/data/preprocess.py` 进行数据清洗。建议进行以下操作：
1. **统一格式**：将所有图片统一转换为 `.jpg` 以减小体积。
2. **尺寸标准化**：YOLO 默认输入大小常为 `640x640`，如果原始图片过大，可利用 OpenCV 预先进行缩放（Resize with padding），从而加快后续训练读取速度。
3. **剔除损坏图像**：用 OpenCV 遍历读取 `cv2.imread()`，如果返回 `None` 则说明图像损坏，需及时剔除该图片及其对应的标签。

## 5. 合并 `archive` 数据集的工作流
1. 检查 `archive1` 和 `archive2` 中标签的 `class_id` 是否定义一致（例如：A 数据集的瓶子是 0，B 数据集的瓶子是 1，这会引发严重错误，必须先写脚本统一）。
2. 将合并后的图片随机打乱，再按照 8:1:1 的比例划分到 `train`、`valid`、`test`。
3. 可使用现成的工具（如 Roboflow 或 Python 脚本）进行合并和划分，切忌手动复制粘贴导致图片与标签错位。
